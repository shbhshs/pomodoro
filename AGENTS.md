# Pomodoro

A Pomodoro timer for iPhone, built with Expo (React Native, TypeScript). This file is the single source of instructions for every coding agent.

## Commands

```bash
npm ci                      # install
npm run check               # typecheck + lint + tests: must pass before every push
npx expo start              # dev server; open in Expo Go on the iPhone via the QR code
npx expo install <package>  # ALWAYS use instead of npm/yarn/pnpm/bun add — resolves SDK-compatible versions
npx expo-doctor             # diagnose dependency and config issues
npx expo install --fix      # fix incompatible package versions
```

## Layout

- `App.tsx` and screens: UI only. Keep them thin.
- `src/`: timer logic and other pure TypeScript. Put the logic here so it can be unit tested without rendering.
- `__tests__/`: Jest tests. Every change to `src/` needs a test.

## Rules

- Never push to `main`. Every change lands through a pull request from its own branch.
- One issue per PR, small diffs. The PR description says what changed and how it was tested.
- Only use native modules that ship in Expo Go for this SDK. If an issue seems to need custom native code, stop and say so in the PR instead of adding it.
- Never edit `.github/workflows/release.yml`, `fastlane/`, `factory.json`, signing settings or secrets. Releases go through fastlane on GitHub Actions, not EAS.
- Do not commit `ios/` or `android/`; they are generated by `expo prebuild` (Continuous Native Generation). Configure native behavior in `app.json` and config plugins.

## Design

The look and layout of every screen are in `docs/design.md`. Follow it for any UI change: colours and sizes come from `src/theme.ts`, never from hex values in a screen. The reference images are in `docs/design/`; open the one for the screen you change and match it.

## Review focus

Reviewers of a change should look hardest at:

- Timer edge cases: pausing, resuming and skipping at the moment a phase ends, and time lost to rounding.
- State that must survive the app being backgrounded: remaining time comes from timestamps, never from counting ticks.
- Off-by-one errors in the focus/break cycle.
- Custom native code, or edits to release, fastlane or signing files. Both are forbidden above.

## Definition of done

`npm run check` passes, new behaviour has tests, and the PR links its issue.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Navigation

When the app needs more than one screen, use **Expo Router**: routes live in `src/app/`, every file there is a screen, and `_layout.tsx` files define navigators. Keep non-route code outside `src/app/`. Docs: https://docs.expo.dev/router/introduction.md

Prefer Expo modules over third-party libraries. Docs: https://docs.expo.dev/versions/latest/index.md
